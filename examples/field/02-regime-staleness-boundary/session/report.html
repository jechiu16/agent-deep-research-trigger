研究問題：Which cache invalidation boundary in Parallax is most likely to prevent stale regime data without increasing coupling?

light
研究建議

若要補強，先加 post-commit read-only health assertion，不改 consumer coupling，也不把現有 non-gating step 直接升為 hard gate。

研究狀態: 複驗修正了問題 framing：目前沒有需要 invalidation 的 active regime cache。

有界結論

結論

不要新增跨模組 cache invalidation。把邊界放在 refresh transaction commit：寫入全成或全不成，commit 後由一個 read-only version/age check 決定下游是否採用；失敗就標 degraded。

核心理由

  • 目前 app pipeline 已不把 regime_history 當 analogue match pool；它只保留讀取失敗的 degraded-subsystem health signal，因此問題不是 active cache invalidation。（Parallax pipeline regime_history health surface）
  • 避免 mixed/stale z-score rows 的最低耦合邊界是 refresh 的單一 DuckDB transaction commit，並在 commit 後以版本與新鮮度檢查決定下游是否採用。（Transactional regime_history z-score refresh）

這次沒有做到的事

  • 若未來 production consumer 持有跨 refresh 的 in-memory cache，需重新定位到該 consumer 的 lifecycle boundary。

  • 新的 production consumer 再次持有跨 refresh 的 regime_history cache。
  • staleness 來源被證明是 transaction 外的長壽命 process cache，而不是 persisted rows。
