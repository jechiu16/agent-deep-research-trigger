## 北極星與範圍

> 幫助強模型在與使用者一同釐清一個不一定有邊界和既有答案的複雜問題時，一個可以幫助他們進行探索並透過落實研究方法形成或幫助形成有效結論的通用框架。

這是供強模型使用的單發研究技能。第五輪只讓研究的入口符合這個目的：模型能先了解情境；對使用者意思或價值取捨有困惑時，主動停下來詢問，等釐清後再開跑。

不新增非絕對必要的機械檢查。不做效果證明、跑分、評測框架、跨次學習或後續結果追蹤；不建立問題圖譜、自動依賴追蹤、必跑的 verifier 或新研究物件。研究方法是模型依問題選用的指引，不是每輪交表的流程。

## 本輪要解除的衝突

SKILL 的入口目前要求只執行 card、只顯示卡片；Boundaries 禁止確認前 inspect the project。這讓模型可能在尚未了解情境時先寫 brief。研究核心的「Ask the user again only for」本來限制重複索取操作授權，卻可能被讀成禁止內容上的澄清。

第五輪修正這兩個衝突，不重寫已完成的研究核心，也不要求使用者先替研究找到答案。

## 目標行為

### 有困惑就主動問，不替使用者補立場

開始研究前，若模型對使用者真正想釐清的問題、用語、目的、優先順序或價值取捨有困惑，先停下來詢問，等待回答後再沿該方向推進。不要用「先假設一下」「研究後再說」或自行選擇看似合理的權重，代替這次澄清。

問題要說清楚困惑在哪、不同理解會怎麼改變方向。可以用具體選項幫助使用者表達，但不設固定問卷、題數、話輪、必填欄位或確認清單。使用者已說清楚的事情不重問；沒有困惑時也不為了符合形式製造問題。

區分「還不知道待研究的事實」與「不懂使用者的意思」。前者可以是確認後要研究的內容，不必要求使用者先回答；後者不能靠更多搜尋替使用者決定。例如，未知效能可以查；不知道「比較好」指效能還是維護成本，就先問。這個例子不成為每題必問的比較維度。

如果使用者本來就想共同探索該重視哪些取捨，理解到這個目的即可，不強迫他先選完偏好才開始。允許問題仍有未知邊界或沒有既有答案；釐清到知道本輪想探索什麼，不等於先把問題框死。

### 本機唯讀定向是允許的方法，不是必經階段

在使用者已放入本次任務範圍的本機專案或檔案內，允許為理解情境、提出必要問題或形成 brief 而做最低限度的唯讀定向，例如讀相關說明、檔案結構或程式入口。對話已足夠時不必先讀專案。

足以提出 brief 就停止定向；一旦發現需要使用者釐清的意思或取捨，就先問，不繼續掃描材料來替他猜。範圍不清楚時先問，不自行搜尋其他專案、家目錄或憑證內容。

確認前仍不連網、不外送資料、不呼叫 provider、不啟動 worker、不執行專案程式或測試、不修改系統或建立研究 package。既有本機 card／profile／registry 讀取保留；唯讀檢視工具不因「只准 card」的舊措辭被一併禁止。

不新增檔案數、時間或步數配額，也不為定向建立另一份日誌。定向所得只是理解情境的材料；若後來作為正式主張的依據，仍須完成既有擷取與查核，不能以「先前看過」取得已驗證資格。

### 釐清與操作授權是不同的事

入口允許卡片之前的自然澄清對話及必要定向說明。意思釐清後才提出正式卡片；卡片本身仍維持現行九行模板與一次明確的 profile／count vector／provider／egress 確認，不新增第二張表。沒有足夠問題內容時先問，不為形式產生空卡片。

回答澄清問題本身不自動等於授權開始研究或追加操作；已明確授權涵蓋的操作也不因此逐次重問。draft／prepare／confirm／init 仍在既有確認流程下執行，不改 CLI 或 hash 綁定。

將研究核心的限制寫清楚為「何時需要重新取得操作授權」，不是「何時才准向使用者提問」。研究途中若才發現同類困惑，先暫停依賴該解讀的推進並詢問；未受影響的授權內工作不因此一律作廢。若澄清導致超出已確認目的或操作範圍，走既有授權流程，不默默擴權。
