## 北極星與範圍

> 幫助強模型在與使用者一同釐清一個不一定有邊界和既有答案的複雜問題時，一個可以幫助他們進行探索並透過落實研究方法形成或幫助形成有效結論的通用框架。框架裡允許、甚至引導強模型一步步推理再推進到下一步；產出不是對話回覆，而是一次經過驗證的研究過程及交付物。

這輪不改一個字的協定。第六輪就是：**完成這一次研究與報告，必要時附幾點實際使用摩擦。** 不預設評估作業，不預設必須再開第七輪。這次的主角是研究問題，不是 skill 自我評估。

## 為什麼這輪由實作方主動

- 第三到第五輪全是靜態改文字。第三輪之後的協定沒有跑過一次真實研究；上一次真跑是 2026-09-08 的 advisor 實驗，用的是第三輪之前的 skill。
- ASTRA 靠靜態審閱在第五輪找到一個自相矛盾。實際使用可能找到更多，但那是順手的副產品，不是這輪的目的。
- 第五輪的「有困惑先問」只有在有真人回答的迴圈裡才會真的發生。

## 這次研究

**使用者的問題（原話）**

> 一個「幫助強模型在與使用者一同釐清一個不一定有答案的負責問題時，一個可以幫助他們進行探索並透過落實研究方法形成或幫助形成有效結論的通用框架」應該長怎樣 有那些工程先例 業界標竿現在都怎麼走 有哪些路線差異 或有那些研究方法參考
>
> standard

**FABLE 的讀法（第五輪入口步驟；卡片 brief 供使用者確認）**

- 「負責問題」讀為「複雜問題」，「不一定有答案」讀為「不一定有邊界和既有答案」：兩者都在北極星定稿時由使用者確認過。
- 「應該長怎樣」讀為：以本 skill 為對照實例，從先例、標竿、路線差異、研究方法推導這類框架應有的形狀與取捨；不是要一份新產品規格，也不是替本 skill 做選型。
- 「工程先例」含兩層：研究代理與 deep research 類系統（主）；工程流程裡逐步推進並驗證的先例，如 ADR、RFC、事故覆盤、TDD（次）。
- 「業界標竿」讀為目前主要 deep research 產品與代理框架的實際做法；「路線差異」讀為設計軸線（host 主導或 provider 主導、驗證深度、人在迴圈的位置、證據鏈的有無等）；「研究方法參考」讀為方法論文獻（系統性回顧、科學方法框架、證據等級、混合主動式互動等）。
- 「應該長怎樣」含價值判斷。現在不必再問，是因為使用者已給出北極星，以及單發、單人、避免冗餘的取捨，不是這題沒有取捨。研究中若真有困惑，仍先問。

**姿態：explore。** 問的是地景與形狀，不是選項間的裁決。仍應交付查明的事實與有依據的綜合，不因 explore 就只交一份產品清單：已查明的事實以 claim 寫入並逐項查核，綜合出來的「形狀」以 observation 與 hypothesis 寫入，不冒充已驗證。代價：這次跑不到 verdict 專屬的 gate，交付說明會註明。

**Profile：standard**（deep 1、search 15、free 不限）。D1 用 rank 1 的 perplexity；search 候選 brave、openalex、sonar 皆 locally-verified，exa 缺 key。依 advisor 實驗，perplexity 一次約 0.6 美元、sonar 每次約 5 美分；上限之內由 host 依需要用，不因為有額度就用完。

**定向範圍**：`agent-deep-research-trigger`、`deep-runs/2026-09-08-advisor-model`、`examples/explore`。不含 `Desktop/研究` 其他內容、家目錄、憑證。advisor 實驗三個 package 已查核的主張是這題一個子題的先前研究：來源可重新擷取後進新 package，其 claim 資格不直接沿用。

**外送**：只有卡片上的研究問題。定向讀到的任何本機內容不進 D1 查詢、不進 search 查詢。`local_file_egress` 維持 false。

**版本**：指引用工作樹的第五輪 `SKILL.md`／`HARNESS.md`；CLI 用本機 clone 的 venv（第五輪未改 runtime，兩者相同）。不混用舊 clone 的指引。是否先 commit 第五輪並同步 clone，由使用者決定；不另做逐檔 hash 名冊。

**位置**：`deep-runs/2026-09-09-framework-shape/session/`（package）。使用摩擦若有，寫在 `deep-runs/2026-09-09-framework-shape/work/friction.md`；沒有就沒有這個檔。

## 使用摩擦怎麼記

正常完成研究；遇到具體矛盾、阻塞或明顯重複負擔時，順手留一句，方便交付時說明。沒遇到就不記。不逐決策點記錄，不盤點未使用段落，不稱為第五輪效果的實測或證明。

## 交付預期

1. canonical package 加 host 親寫的 `report.html`，依第五輪協定如實結尾：EXPLORED 或 BLOCKED，不美化。
2. 簡短交付說明：跑了什麼、花了多少、壞了什麼、哪些主張沒查到。
3. 若遇到具體重複、矛盾或不必要負擔，SKILL 與 HARNESS 都可以提減法建議；沒發現值得改的就不交。研究所得可以啟發修改，但不自動授權修改。

## 不做什麼

- 跑的途中不改 SKILL、HARNESS、測試。協定擋住什麼就照協定做；覺得協定錯了也先照做，交付時說明。
- 不加機制、欄位、gate、status、評測框架。不宣稱一次研究能證明或推翻任何一句指引。
- 遇到 runtime 阻塞，如實說明，依現有方法處理或詢問，不自行修 runtime，不把框架維修混入研究。另外交付不等於另外取得授權。
- 研究結論本身（框架應該長怎樣）交給使用者判斷，與 skill 演進分開。
- 不增加特別觀察任務：該問時問，不替使用者猜立場；沒有困惑也不製造提問來測流程。

## 限制

- host 是被評估文字的作者；這輪不做自評，摩擦只留一句。
- 一題，而且是關於研究工具本身的 meta 題目，與 advisor 實驗 C 輪 J1 同樣的外推限制。
