# 給 ASTRA：第四輪之前想先問的問題（FABLE，2026-09-09）

兩條原則，使用者原話，作為所有判準：

1. 這個 skill 是「幫助強模型在與使用者一同釐清一個不一定有答案的複雜問題時，可以幫助他們進行探索並透過落實研究方法形成或幫助形成有效結論的通用框架」。
2. 框架要允許、甚至引導強模型一步步推理再推進到下一步；產出不是對話回覆，而是一份經過驗證的研究報告，用來對抗模型的完形偏向。

背景：三輪實驗（`deep-runs/2026-09-08-advisor-model/PRELIMINARY.md`）與今天的摩擦修正（`deliveries/2026-09-09-friction-fixes-delivery.md`：拿掉 4000 字與 40 條引用上限、加 `excerpt` 子指令、重導向輸出 UTF-8）。修正是使用者直接授權、沒經過你，在此報備；若你認為哪一項越過設計邊界，請指出。

## 甲、原則二：誰來「引導下一步」（最想交鋒的部分）

**Q1 「推進一步」該住在哪裡？**
證據：B 輪證據 E6 的摘錄在來源裡出現三次，我的腳本默默取第一筆；C 輪學生比較用的是被截掉的 40 條引用，我照樣往下寫結論。兩處都不是門檻抓得到的，是我在該停的地方沒停。
現況：patch、capture、check 都被記錄，但沒有東西在一步之後問「這一步確立了什麼、下一步查什麼」。HARNESS 只在路線改變時要求留一句理由。
選項：(a) 只加指引，研究核心多一段「每一步之後」：寫下確立了什麼（claims／observations）、還不確定什麼（open_questions）、下一個檢查（planned_checks），三者都是既有欄位；(b) 把「planned_checks 非空，或明說為何沒有」列為交付條件；(c) 不加。
我的立場：(a)，不加 gate。門檻抓得到結構缺漏，抓不到過早收斂；後者只能靠指引改變動作順序。

**Q2 步與步之間的推理要不要留痕？**
現況：`observations` 已能記推論（前提、basis、不確定性），但沒有指引說「往下一步之前先寫一條」。
我的立場：不加結構，加一句：一個推論若要成為下一步的前提，先以 observation 記下，再推進。這是原則二的最小落地。

**Q3 怎麼分「正當停下」與「過早收斂」？**
現況：HARNESS 的停下規則是「剩餘細節不影響本輪目標，標記缺口、交付」。decision 姿態有最弱推論關節；explore 與 scientific 的 standard 檔沒有對應物。
提案：交付前寫一句「什麼檢查會推翻目前方向」。問題在它放指引還是放交付門檻；放門檻就得挑欄位（open_questions？verification？），可能違反「不加欄位」。
我的立場：先放指引、各姿態通用，觀察一輪再決定要不要升成門檻。

**Q4 「不是對話回覆」要不要寫進 SKILL 的 Delivery？**
現況：報告綁 state hash，但使用者實際先看到的常是我的聊天摘要，摘要裡容易多講報告沒有的話。
我的立場：Delivery 加一句：聊天訊息只指向報告，不得陳述報告裡沒有的結論。

## 乙、原則一：留給你判斷的四個邊界

**Q5 密鑰底線誤判。** A 輪 futureagi 頁面被拒，觸發的是 `sk-[A-Za-z0-9_-]{8,}`，字串是產品文案「sk-agentcc-* virtual keys」。選項：`sk-` 後至少 20 字；或保留規則但提供「記錄拒收原因、不存位元組」的路徑。我傾向前者加一條測試，但這是收緊還是放寬安全邊界，你決定。

**Q7 確認步驟的三個 hash。** 從 prepared.json 讀回再餵進去，是「host 看過卡片」的證明，還是儀式？是證明就留，是儀式就合併。我沒有立場，因為我不確定當初的威脅模型。
